HTTP 预检请求（Preflight Request）是与跨域资源共享 (CORS) 相关的一个机制。当使用跨域 HTTP 请求时，浏览器会在实际请求发送之前自动发送一个“预检”请求，以确定目标服务器是否允许该跨域请求。预检请求是由浏览器自动发起的，不需要开发者手动编写代码来发起它。

### 1. **CORS 背景和跨域问题**

CORS 是一种浏览器机制，它允许通过安全的方式来处理不同源之间的资源请求。跨域请求涉及安全性，因为它允许一个网站向另一个域名的服务器请求资源。为了防止不安全的请求，浏览器使用了严格的跨域请求规则。

通常情况下，当一个网页在向不同域名的资源发出请求时（例如从 `https://example.com` 向 `https://api.anotherdomain.com` 发送请求），浏览器会检查请求是否符合同源策略。同源策略是一种安全机制，它确保只有同一来源（域名、协议、端口）的资源才能相互访问。

CORS 允许服务器明确声明哪些源允许访问资源，并且可以对某些敏感的 HTTP 请求进行预检，以确保请求的安全性。

### 2. **什么是预检请求**

预检请求是浏览器在实际跨域 HTTP 请求之前发送的一个 `OPTIONS` 请求，用于确定服务器是否允许该跨域请求。这种请求通常会在以下情况下触发：

- 请求使用了复杂的 HTTP 方法（例如 `PUT`、`DELETE`、`PATCH`，而不仅仅是 `GET`、`POST`）。
- 请求使用了一些特殊的 HTTP 头字段，如 `Content-Type: application/json`、`Authorization` 等。
- 请求包含了非简单的内容类型，如 `application/json`、`application/xml`。

#### 简单请求和预检请求的区别：

- **简单请求**：如果请求是使用 `GET`、`POST` 或 `HEAD`，并且只使用了一些简单的 `Content-Type`，如 `text/plain`、`multipart/form-data` 或 `application/x-www-form-urlencoded`，并且没有使用自定义头字段，浏览器会认为这是一个简单请求，不会发起预检请求。
- **预检请求**：如果请求不符合简单请求的条件，浏览器会在实际请求之前发起一个 `OPTIONS` 预检请求，询问服务器是否允许实际请求的执行。

### 3. **预检请求的流程**

1. **发送预检请求**：

   - 浏览器向目标服务器发送一个 `OPTIONS` 请求。
   - 预检请求包含了以下主要的 HTTP 头字段：
     - `Origin`：发起请求的页面的源（协议、域名、端口）。
     - `Access-Control-Request-Method`：浏览器将要使用的实际请求方法，例如 `POST`、`PUT`、`DELETE`。
     - `Access-Control-Request-Headers`：浏览器将要发送的自定义请求头字段列表，如 `Content-Type`、`Authorization` 等。

   **预检请求示例**：

   ```http
   OPTIONS /some-resource HTTP/1.1
   Host: api.anotherdomain.com
   Origin: https://example.com
   Access-Control-Request-Method: POST
   Access-Control-Request-Headers: Content-Type, Authorization
   ```

2. **服务器响应预检请求**：

   - 服务器收到预检请求后，检查请求的 `Origin`、`Access-Control-Request-Method` 和 `Access-Control-Request-Headers`，并根据服务器的配置决定是否允许这个跨域请求。
   - 如果服务器允许该请求，它会在响应中包含一些特定的 CORS 头字段。

   **预检请求的响应示例**：

   ```http
   HTTP/1.1 204 No Content
   Access-Control-Allow-Origin: https://example.com
   Access-Control-Allow-Methods: POST, GET, OPTIONS
   Access-Control-Allow-Headers: Content-Type, Authorization
   Access-Control-Max-Age: 86400
   ```

   - `Access-Control-Allow-Origin`：指定哪些源可以访问资源。
   - `Access-Control-Allow-Methods`：列出允许的 HTTP 方法，如 `POST`、`GET`、`OPTIONS`。
   - `Access-Control-Allow-Headers`：列出允许的自定义头字段。
   - `Access-Control-Max-Age`：表示此响应可以被缓存多长时间，以秒为单位。下次相同的跨域请求可以直接使用缓存结果，而不需要再次发起预检请求。

3. **浏览器处理服务器的响应**：
   - 如果服务器响应了允许的跨域请求，浏览器会继续发送实际的 HTTP 请求。
   - 如果服务器不允许跨域请求，浏览器将中止请求，并且前端代码无法访问响应数据，通常会触发跨域请求失败的回调。

### 4. **预检请求的重要性和影响**

- **安全性**：预检请求允许服务器控制跨域请求的访问权限，确保不受信任的请求不会访问敏感的资源。
- **性能开销**：预检请求增加了一次额外的请求，这会导致性能开销，尤其是在频繁的跨域请求中。为了解决这个问题，可以通过配置 `Access-Control-Max-Age` 来缓存预检请求的结果，减少实际请求中的预检开销。

### 5. **如何避免预检请求**

在某些情况下，开发者可能希望避免预检请求，以减少网络开销。以下是一些常见的方法：

- **使用简单请求**：通过使用 `GET` 或 `POST` 请求，并避免使用自定义头字段或非简单的 `Content-Type`，可以避免触发预检请求。
- **减少自定义头字段**：尽量减少或避免使用自定义头字段，如 `Authorization`，可以有效减少预检请求的触发。

- **预检请求的缓存**：通过配置 `Access-Control-Max-Age`，可以将预检请求的结果缓存一段时间，从而避免短时间内的重复预检请求。

### 6. **示例总结**

```http
// 预检请求
OPTIONS /api/data HTTP/1.1
Host: api.anotherdomain.com
Origin: https://example.com
Access-Control-Request-Method: PUT
Access-Control-Request-Headers: Content-Type

// 预检请求的响应
HTTP/1.1 200 OK
Access-Control-Allow-Origin: https://example.com
Access-Control-Allow-Methods: GET, POST, PUT, DELETE
Access-Control-Allow-Headers: Content-Type
Access-Control-Max-Age: 3600

// 实际请求
PUT /api/data HTTP/1.1
Host: api.anotherdomain.com
Origin: https://example.com
Content-Type: application/json
...
```

在这个流程中，预检请求确保了跨域请求的安全性，避免了未经授权的跨域访问，同时也引入了额外的网络开销。理解预检请求对于设计和优化跨域请求非常重要。
